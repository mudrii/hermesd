# hermesd 2026.9.26

Follow a busy Hermes Agent with clearer warnings, richer usage history, and a
dashboard that stays responsive as your workspace grows.

This release covers the changes since **v2026.9.13**. hermesd remains a
standalone, read-only dashboard: it does not import Hermes Agent code or modify
your Hermes home. New views appear when the corresponding upstream records exist.

[GitHub release](https://github.com/mudrii/hermesd/releases/tag/v2026.9.26) ·
[PyPI package](https://pypi.org/project/hermesd/2026.9.26/) ·
[Changes since v2026.9.13](https://github.com/mudrii/hermesd/compare/v2026.9.13...v2026.9.26)

## See what needs attention

- Pause/ESTOP status, gateway memory pressure, restart-loop warnings, dead
  delivery targets, and restart backlogs make operational trouble easier to spot.
- Gateway degradation, multiplexing, unfinished migrations, and update skew
  now reflect the current upstream state and distinguish missing evidence.
- Recent cron failures stay visible after newer successful runs. Delivery
  queues, deferred bot-chat receipts, recovery ledgers, and provider holds
  explain delayed work without exposing message payloads.

## Understand activity and usage

- Explore 14-day token history, usage by source, top sessions, repository
  activity, and an hourly activity sparkline.
- Inspect per-job cron token usage, model selection, and provider holds.
- See integration status, provider/model cooldowns, Skills Hub counts, storage
  use, state snapshots, and pending operator reviews.

## Move through the dashboard more easily

- Every detail view supports scrolling; detail snapshots include the full
  panel rather than stopping at the terminal height.
- Short terminals get a layout that keeps panel content visible. Log tabs
  wrap according to the available width.
- Input handling, session sorting, and terminal text rendering are more
  consistent. Cached rendering and fewer repeated database snapshots reduce
  work during unchanged refreshes.

## Navigation, CLI, and snapshots

- `j`/`k` and `g`/`G` reach every detail view's content. Logs retains its
  selected-stream viewport; other panels scroll their complete rendered detail.
  These keys do nothing in the overview.
- Escape closes help first, otherwise stops filter editing, otherwise returns
  from detail to overview. Enter also finishes filter editing. Application-mode
  arrows, F1–F4, and Alt+key sequences no longer accidentally exit detail views.
  A combined input such as `r2` refreshes and then opens Sessions.
- Wide layouts require at least 34 rows; the compact layout requires 26.
  Shorter terminals use a reduced two-panels-per-row overview.
- `--snapshot-panel N` exports full detail instead of clipping it at 48 lines.
  Both `0` and `00` alias Memory (panel 10); registered panels are 1–13.
- `--refresh-rate` accepts integer seconds from 1 to **86400**, default 5.
  Empty home/output paths are rejected, and argument errors name valid values.
  An unreadable Hermes home produces a clear snapshot error rather than a traceback.
- `--snapshot-file` cannot write inside the Hermes home, including path aliases
  on case-insensitive filesystems.
- Displayed log tails and cron excerpts use `--log-tail-bytes` (positive integer,
  default 32768). Log-health scans have a separate **256 KiB per stream per
  refresh** cap and initially work through at most a 2 MiB tail under that cap.
  Truncation or replacement restarts the health scan.

## Stronger privacy and recovery

- Redaction covers session titles, display names, activity/error text, usage
  analytics, credentials, cookies, signatures, and secret-bearing webhook URLs.
- Nonblocking regular-file reads prevent FIFOs, including files swapped during
  an open, from wedging collection. Structured version reads are confined and
  bounded; oversized input is rejected instead of partially parsed.
- Failed memory, SOUL, and skill reads preserve last-good data, report degraded
  sources, and retry when access returns. Independent sources continue updating.
- Malformed state, disappearing files, deep structured data, and enormous token
  counts no longer cause the reported crashes or misleading empty values.
- Redaction happens before clipping delivery/platform errors, cron errors,
  delegation goals/errors, and session free text. Untrusted brackets also render
  literally without stray escape characters.
- A malformed database table affects its own source rather than failing unrelated
  readers. Files deleted after a successful read degrade for one refresh and then
  become absent. Corrupt job, channel-directory, and spawn-ledger data is marked
  stale instead of appearing healthy.
- Cache identities include modification time, size, and inode. WAL snapshots
  detect concurrent checkpoints and retry without copying the source `-shm` file.
  Hooks, checkpoints, drain markers, dashboard manifests, and profile log streams
  remain confined to their owning home.

## Performance and validation

Unchanged WAL databases reuse private snapshots; detail rendering reuses cached
lines until data, width, or view settings change. macOS process identity uses
kernel `sysctl` reads, with a bounded `ps` fallback for unresolved PIDs. Repeated
redaction, timestamp parsing, process checks, and home-confinement work are cached;
cron history fetches only the ten rows displayed. This also fixes process identity
checks failing when one PID exceeds 99999.

The changelog records measurements on a representative home: repeat collection
fell from about 90 ms to 25 ms, and idle/scroll detail rendering from about 35 ms
to 1 ms. Actual timings and avoided temporary I/O depend on the host, data size,
and how often the Agent writes.

The release commit passed the
[main CI run](https://github.com/mudrii/hermesd/actions/runs/36250385627), including
Python 3.11–3.14, macOS, Docker, and Nix on Linux/macOS for x86_64 and ARM64.
The [publication workflow](https://github.com/mudrii/hermesd/actions/runs/36294947558)
rechecked eligibility, the Python matrix, dependency audits, and wheel/source
installation before publishing. The local suite recorded 3,563 passed, one
optional live-home test skipped, and 98.80% coverage. A fresh PyPI installation
passed text/JSON snapshot and read-only smoke checks.

## Compatibility and upgrade notes

- Python **3.11 or newer**, **Linux or macOS**, and an existing Hermes Agent home
  are required. Install into a separate environment from the Agent. Older Agent
  schemas retain supported fallbacks; optional sections require their source records.
- Direct PyPI runtime pins are Rich 14.3.3, PyYAML 6.0.3, and Pydantic 2.13.4.
  Docker uses the lockfile; Nix uses its independently tested package set.
- Root mode remains the default. `--profile NAME` or `HERMES_PROFILE` opts into
  profile-scoped data; hermesd does not follow `active_profile` automatically.
- Extremely large display counts use explicit saturation labels. JSON retains
  the collected numeric values.
- A log tail beginning inside a line drops that partial line to avoid exposing
  a cut-off secret. A single line longer than the configured tail budget can
  therefore produce no displayed text.
- Screenshots use synthetic fixtures and illustrate the current interface.

Upgrade using the method that installed hermesd:

```bash
# Existing uv tool installation
uv tool upgrade hermesd

# Existing pip installation: activate its isolated virtual environment first
python -m pip install --upgrade hermesd

# Existing pipx installation
pipx upgrade hermesd

# Confirm the installed version
hermesd --version
```

For this exact release, pip accepts `hermesd==2026.9.26`. Source installations
can select `git switch --detach v2026.9.26` in a clean checkout and reinstall;
local Docker builds use that checkout. Nix users can run
`nix run github:mudrii/hermesd/v2026.9.26`. See the
[installation guide](../../README.md#installation) for complete setup instructions.

### JSON snapshot migration

The exported JSON envelope contains `panel_num`, `panel_name`, and **`state`**.
Dashboard fields are children of `state`; `--snapshot-panel` annotates the export
but still includes the full state. Consumers must update these paths:

| Previous field or value | Replacement / behavior |
|---|---|
| `state.skills_memory.credential_pools[].cooldown_remaining` | `cooldown_remaining_seconds` is a positive number when a pool cooldown is derived, otherwise `null`; `model_cooldowns` lists per-model cooldowns that may still apply. Do not parse the old display string. |
| `state.cron.jobs[].model_snapshot` and `provider_snapshot` | Read `effective_model` and `model_source`; these describe effective model selection, not a one-for-one provider replacement. |
| `state.migration.verification_gap == "flag_off"` | This value is no longer emitted; the retired multiplex flag is not part of topology verification. |

New fields under `state` include `usage_analytics`, `cron_usage`, `cron_deliveries`,
`cron_bot_chat`, `cron_recovery`, `disk`, and `integrations`. Existing objects also
gain fields, including `runtime.estop_*`, `logs.health`, `operations.snapshots`,
`operations.pending_actions`, `profiles.duplicate_platform_credentials`, and
gateway warning/history fields. Parsers should tolerate unknown fields.

For example, this **partial** snapshot shows the nesting (other fields omitted):

```json
{
  "panel_num": 6,
  "panel_name": "Cron",
  "state": {
    "cron": {
      "jobs": [{"effective_model": "example-model", "model_source": "pinned"}]
    },
    "skills_memory": {
      "credential_pools": [{"name": "example-provider", "cooldown_remaining_seconds": null, "model_cooldowns": []}]
    },
    "usage_analytics": {"daily": []}
  }
}
```

Read the new analytics field as `payload["state"]["usage_analytics"]`; the
`state` envelope itself has not moved. Existing consumers of cooldown display
strings should use `entry["cooldown_remaining_seconds"]`, handle `None` without
converting it to a duration, and inspect `entry["model_cooldowns"]` separately.
